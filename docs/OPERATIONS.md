# 运维指南

本文档是给部署者看的：桥跑起来之后怎么看它健不健康、坏了怎么修、
备份怎么做。命令速查见 README.md。

## 健康三层

1. **systemd**：服务进程退出一律自动重启（`Restart=always`）。
   v5 起 `Type=notify` + `WatchdogSec=180`：轮询循环卡死时 systemd
   自己重启；`systemctl reload` = SIGHUP = 重读 proxy.env，不丢线程、
   队列和会话。
2. **5 秒巡检 hook**：除任务检测外，还检测服务健康——进程存活且以
   PID + 命令行双重核验；进程活着但 3 分钟无成功轮询也判不健康
   （官方 -14 暂停期除外）。不健康时先 SIGHUP，20 秒没恢复才重启服务；
   同一持续故障每小时最多报警一次，恢复健康即清零。
   注意：hook 定义的巡检间隔不要低于 5 秒，低于 5 秒会被平台判定无效。
3. **每小时兜底检查**：主防线是 hook 的巡检，这里只兜底 hook 本身失效
   的情况。健康时静默，不健康时执行同样的恢复流程。
   模板见 `hooks/health-cron.example.md`，按你自己的调度器填写。

常用检查：

```bash
python3 bridge.py status     # 脱敏状态
python3 ops/doctor.py        # 18 项健康检查
python3 ops/report.py --days 1
```

## 恢复

- 服务掉了、单元文件丢了（例如虚拟机被换掉后 `/etc` 丢失）：
  `bash ops/recover.sh`，它会从项目目录里的单元文件重新安装并启动，
  然后等一次成功轮询。
- 服务还在但不健康：`bash ops/repair.sh`。
- 登录失效（`auth` / `credentials_missing`，或 doctor 报登录异常）：
  不要自行生成二维码。停服务 → `python3 bridge.py login --force` →
  扫码 → `python3 bridge.py wait-login` → 启动服务。
- 执行者中途死亡的任务：executing 超过 10 分钟无心跳会被收回，
  下一个执行者按断点续跑；内存里没落盘的工作续不上，长任务要拆小发。

## 备份

- `bash ops/backup.sh` 生成带日期快照；时间戳一律用 America/Caracas。
- 留存：最近 5 份带日期快照 + 每次改动前一份 + 里程碑，超出部分绝不自动删除。
- 超出清理的推荐流程（缺一不可）：
  1. 先留一份总快照。
  2. 把超出部分做成脱敏包：不含 `state/`、不含 `credentials.json`。
  3. 上传到你自己的云盘，在列表里核对到文件名和大小。
  4. 逐字节核对本地文件与包内条目，只删已进包且字节一致的部分。
  5. `state/` 副本一律保留本地，命名快照不动。
- `ops/backup.sh --prune-list` 只列还剩非 state/ 文件的超出快照；
  `--prune` 删前先留总快照、只删非 state/ 文件，它只是上云核对之后的
  本地删除一步，不能代替上云流程。
- 快照里的 bridge.py 若与上一份快照哈希相同会用硬链接去重：
  磁盘上只占一份，删掉其中一份不影响另一份；不要就地编辑硬链接的
  快照文件，要改先拷出来。

## 常见故障

| 现象 | 先查什么 | 处理 |
| --- | --- | --- |
| 微信里显示无法连接 | `systemctl status`、`ops/doctor.py` | 单元丢了用 `recover.sh`，服务不健康用 `repair.sh` |
| 任务一直 pending 没人领 | hook 定义是否有效、巡检间隔是否 ≥ 5 秒 | 修定义后等一次巡检，不要反复重启服务 |
| 正在输入消失了、但任务还在执行中 | 任务状态，不是输入提示 | 输入提示是瞬时 UI 状态，新消息到达或客户端超时就会清掉；以任务状态为准 |
| 回复发了一半、后面没了 | 回复额度 / 24 小时窗口 | 超额部分已挂起，用户下一条消息时自动续发，不要重发 |
| 语音条发出去对方看不到 | 是否走了原生语音 | 默认应走文件卡片；只有显式设 `WECHAT_BRIDGE_NATIVE_VOICE=1` 才尝试原生语音条 |
| 图片/视频发不出去 | 大小与压缩阈值、CDN 上传 | 看 `media_error` 里的具体原因，不要只重试 |

## 监控数字怎么看

- `status` / `stats` 里的延迟分段：wake（唤醒）、exec（执行）、
  deliver（投递）。投递中位数通常不到 1 秒；执行时间是执行者干活的
  时间，不是桥的速度。
- `observed_limits`：服务端实际允许的回复条数，空表示还没观测到，
  10 仍是默认值；不要用假消息去探测它，那会骚扰机主自己的微信。

## 代理与媒体安全（v5.0.1 起）

- 代理池只支持 http:// CONNECT 代理；https/socks 代理会停用池子并记日志，
  不要把“池子已停用、走 urllib 回退”当成已接管。
- 服务端给的下载/上传地址只放行 https 的腾讯 CDN 域名（`*.qq.com`、`*.qpic.cn`、`*.qlogo.cn`），其余一律拒绝；
  本地测试用 `WECHAT_BRIDGE_MEDIA_ALLOW_LOCAL=1` 放行回环地址。
- AES 优先 cryptography，其次系统 libcrypto，都没有才回退 openssl 命令行
  （回退时记警告；生产机建议装 cryptography）。

## SIGHUP 代理切换的生效时机（v5.0.3 起）

- SIGHUP 让 serve 重读 proxy.env，但切换在**下一个轮询周期**才生效：
  切换那一刻已经在途的长轮询仍走旧连接完成，消息正常投递、不会丢；
  下一次轮询才走新代理。测试里不要在切换后立刻断言隧道数，
  应先等一次代理轮询出现。
